# Web API

Webサービス同士をHTTPなどでつなぎ、データや機能をやり取りする仕組み。

- HTTP・JSON
- REST API
- API設計
- 認証・認可
- DB連携
- API連携
- テスト・セキュリティ

## 通常のWebサイト

ブラウザで、`https://tracenote.work/traces`へアクセス:

```bash
ブラウザ: tracesを見せて下さい
  |
Laravel: DBからTraceを取得 -> BladeでHTML生成 -> HTMLをブラウザへ返す
  |
ブラウザ: 受け取ったHTMLを画面として表示
```

=> サーバー側で画面そのものを作って返している

## APIのイメージ

```bash
ブラウザ / スマホアプリ / 別のプログラム
    |
例: GET /api/traces
    |
Trace一覧下さい
    |
Laravel: DBから取得 -> JSONを返す
    |
JSONを受け取る
```

## Web APIを利用する構成

```bash
フロントエンド: データください
    |
Laravel API: DB -> データ取得
    |
    | JSON
    |
フロントエンド: 受け取ったJSONでHTMLを生成
    |
画面に表示
```

=> この場合、何を表示するかやどういう見た目にするかという部分をフロントエンド側が担当できる

Laravel側をバックエンドとして、`React`, `Vue`, `スマホアプリ`, `別のWebサービス`などのフロントエンドがAPIを利用できる。

Laravel側は、「誰が画面を作るのか」をあまり意識せず、「このデータ・機能を、このルールで提供する」という役割に集中できる。

> 通常のWebアプリでは、サーバー側がデータ取得からHTML生成まで行い、完成したHTMLをクライアントに返す。
> Web APIでは、サーバー側がデータや処理結果をクライアントが扱いやすい形（例えばJSON）で返し、
> クライアント側がそのデータを使って表示などを行える。
