## Part 1: ビルドの裏側を知る（ターミナル派）

Qt Creator の `Cmd + B` が裏で何をしているかを、ターミナルで1つずつ確かめる。

### なぜやるのか

- ビルドエラーで困ったときに、どこで失敗しているかを自分で切り分けられるようになる。
- メインの課題で出てくる `moc_*.cpp` や `ui_*.h` の正体が分かる。
- Linux や組み込みの開発では、IDE を使わずに make や CMake でビルドすることが多い。

| # | 内容 | 学ぶこと | 状態 |
|---|---|---|---|
| M1-1 | [ターミナルで qmake → make](lessons/m1-01-qmake-make.md) | `qmake` が `Makefile` を作り、`make` がそれを実行する流れ。`Makefile` を自分で書く・読む。警告を読む | 🟨 |
| M1-2 | moc の正体 | `Q_OBJECT` があるクラスから `moc` が何を生成するか。シグナルが「ただの関数」として実装される仕組み | ⬜ |
| M1-3 | uic の正体 | `.ui`（XML）が `ui_*.h`（C++）に変換される流れ。`setupUi()` の中身を読む | ⬜ |
| M1-4 | qmake を使わずにビルドする | `clang++` だけで Qt アプリをビルドする。インクルードパスやリンクの指定を、自分で書いてみる | ⬜ |
| M1-5 | CMake でビルドする | 同じプロジェクトを `CMakeLists.txt` でビルドする。qmake の `.pro` と比べる | ⬜ |
| M1-6 | （任意）Linux でビルドする | Docker で Ubuntu を動かし、同じプロジェクトを Linux でビルドする | ⬜ |

- 練習用のプロジェクトは、レッスンを始めるときに一緒に決める（例: 自作のシグナルを持つ小さなクラスがあるもの）。
- M1-5 では CMake のインストール（`brew install cmake`）が必要。
- M1-6 は、Part 1 の締めくくりとして、やるかどうかをそのときに決める。
